## Четыре грабли дня — кандидаты в GOTCHAS

- **`.sql`, снятый из лога Actions, содержал строки echo-блока раннера в caret-нотации**
  (`^[[36;1mdocker exec … pg_dump …^[[0m`). Это **текст** `^`+`[`, не ESC-байты: `grep -P '\x1b'`
  и python-поиск `\x1b` слепы, psql падает на `^`. Поймала репетиция dry-run на проде;
  без неё apply уронил бы миграцию на живой базе. Урок общий: артефакт, вынутый из лога
  через буфер обмена, обязан проходить machine-проверку, а не глазами.
- **Второе двоеточие в `name:` шага делает воркфлоу невалидным молча.** GitHub не красит
  такой файл в PR: воркфлоу показывается по пути вместо имени, `gh workflow run` отвечает
  422 «нет триггера workflow_dispatch», push в ветку даёт красный без лога. Два PR прошли
  зелёными с битым файлом. Гейт `yaml.safe_load` по `.github/workflows/*.yml` в CI — у нас
  в PENDING, стоит одного шага.
- **gitleaks сканирует историю ветки, а не diff.** Литерал `-H "X-API-Key: not-a-real-key"`
  в пробе шлюза красит PR по `curl-auth-header`; фикс следующим коммитом **не лечит** —
  старый коммит остаётся в истории. Лечение — пересобрать ветку одним коммитом от `main`.
  Правило для проб: заведомо неверный ключ собирать в переменной, не литералом.
- **curl с раннера GitHub до myjino-хоста Сетки — таймаут (exit 28)**, при том что vault
  на том же хостере с раннера отвечает. Пробы шлюза выполняем с бокса. Совпадает с нашей
  же граблей смоука в `apply-form-secrets.yml` (run 29641380411).
