## 2. Критические недочёты

### 2.1 Скорость (Core Web Vitals)
- 27.9 с полной загрузки и 1.6 МБ HTML — Яндекс и Google понижают такие сайты; посетители с мобильного интернета уходят.
- Причины: WPBakery генерирует мегабайты inline-разметки; Popup Maker кладёт конфиги **всех** попапов на каждую страницу; RevSlider + slick — два слайдера сразу; reCAPTCHA v3 грузится на всех страницах, даже без форм.
- **Мёртвый груз:** старый Universal Analytics (`analytics.js`, UA-46179802-24) не работает с июля 2023 — грузится зря; gtag подключён дважды (UA + G-1HT7VBDGYW).
- Google-сервисы (reCAPTCHA, gstatic, GA) из РФ отвечают нестабильно — тормозят загрузку и **ломают отправку форм** (см. 2.4).

### 2.2 SEO on-page
- **Title главной** — только название компании. Главные коммерческие запросы («капитальный ремонт дизельных двигателей», «ремонт ЯМЗ» и т.д.) в title не участвуют.
- **Meta description главной обрезано на полуслове** («…настройку и регулировку»). У разделов «Услуги», «Продукция», «Контакты», «Новости» описаний **нет вовсе**; у «Вакансий» — мусор «Звоните по телефону: tel:+79828108169».
- **H1 главной** дублирует title (название АО), вместо услуг.
- **37 из 53 изображений без alt** — картиночный поиск и доступность потеряны.
- **og:image нет** — при шаринге в VK/Telegram/WhatsApp ссылка без картинки.

### 2.3 Структурированные данные — ноль
На сайте **нет ни одного JSON-LD блока**: ни `Organization`, ни `LocalBusiness`, ни `Service`, ни `Product`, ни `BreadcrumbList`, ни `FAQPage`. Rank Math установлен, но схема не настроена. Это главный упущенный рычаг и для сниппетов поисковиков, и для ИИ-ответов.

### 2.4 Формы и конверсия
- Формы CF7 защищены **Google reCAPTCHA v3** — из РФ скрипт периодически не грузится → заявка молча не уходит. Замена: Yandex SmartCaptcha / серверная honeypot-защита.
- Тексты на слайдах «вшиты» в картинки: не индексируются, не читаются скринридерами, нечитаемы на мобильном.

### 2.5 Безопасность/гигиена
- Нет security-заголовков (HSTS, X-Content-Type-Options, CSP, Referrer-Policy).
- Открытый `wp-json` REST API (перечисление контента и потенциально пользователей), `admin-ajax.php` разрешён в robots.
- WordPress + 8 плагинов = постоянная поверхность атак и обязанность обновляться.

## 3. GEO — видимость в ответах нейросетей (ChatGPT/Alice/GigaChat/Perplexity)

Что LLM-поисковики берут в ответ и чего сайту не хватает:

1. **`llms.txt` отсутствует** — новый стандарт «карты сайта для LLM» (список ключевых страниц + краткое описание компании в markdown).
2. **Нет политики для ИИ-краулеров** в robots.txt (GPTBot, ClaudeBot, PerplexityBot, YandexBot for GPT). Сейчас всё разрешено «по умолчанию» — для завода это правильно (нам НУЖНО попадать в ответы), но политику стоит зафиксировать явно.
3. **Факты не машиночитаемы.** LLM цитируют то, что легко извлечь: таблицы «модель двигателя → услуга → срок → гарантия», списки, Q&A. Сейчас ключевые факты размазаны по абзацам.
4. **Нет FAQ.** Страницы «Сколько стоит капремонт Д6?», «Какая гарантия?», «Как отправить двигатель в ремонт?» с разметкой `FAQPage` — главный формат, который LLM пересказывают дословно.
5. **Серия статей про Д6 — правильное направление** (42 поста, техруководства по диагностике/эксплуатации/консервации) — именно такой экспертный контент LLM берут в источники. Усилить: разметка `TechArticle`, автор, даты, перелинковка со страницами услуг.
6. **Внешние сигналы:** корректный NAP (название-адрес-телефон) в Яндекс Бизнес, 2ГИС, отраслевых каталогах (korabel.ru уже упомянут в закупках), упоминания в СМИ — LLM сверяют факты по нескольким источникам.
7. **Уникальная позиция не проговорена текстом.** «Один из немногих заводов РФ с испытательными стендами дизелей», «ремонт с 1931 года», «2000+ заказчиков» — эти утверждения должны быть на видных местах в чистом тексте, а не в картинках.

## 4. План улучшений

### 4.1 Quick wins на текущем WordPress (можно сделать до переезда)
1. Переписать title/description всех разделов (шаблон: «Капитальный ремонт дизельных двигателей {серия} — Малмыжский ремзавод, вся Россия»).
2. Включить в Rank Math схемы Organization + Service + Article, прописать og:image.
3. Удалить Universal Analytics и дубль gtag; вынести Метрику в отложенную загрузку.
4. Заменить reCAPTCHA на SmartCaptcha; убрать `user-scalable=0`; проставить alt.
5. Добавить `/llms.txt`; security-заголовки на nginx.

### 4.2 Стратегически — новый сайт (этот репозиторий)
- **Стадия 1 (сделано здесь):** копия текущего сайта на Next.js 15, статический экспорт: HTML страницы ~10-30 КБ вместо 1.3 МБ, загрузка <1 c, Core Web Vitals в зелёной зоне; JSON-LD Organization + canonical + sitemap/robots из коробки; формы без Google-зависимостей.
- **Стадия 2 (новый UI/функционал):** Payload CMS (стандарт экосистемы) для новостей/каталога, реальный бэкенд форм с уведомлениями, FAQ-хаб с разметкой, каталог «двигатель → услуги → запчасти» со схемой Product/Service, llms.txt, Метрика с фильтрами (G136), SmartCaptcha.
- **Контент-хаб:** развивать серию техстатей (Д6 → ЯМЗ → гидропередачи), связывая каждую статью с посадочной услуги.
