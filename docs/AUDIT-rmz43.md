## 2. Критические недочёты

### 2.1 Скорость (Core Web Vitals)
- 27.9 с полной загрузки и 1.6 МБ HTML — Яндекс и Google понижают такие сайты; посетители с мобильного интернета уходят.
- Причины: WPBakery генерирует мегабайты inline-разметки; Popup Maker кладёт конфиги **всех** попапов на каждую страницу; RevSlider + slick — два слайдера сразу; reCAPTCHA v3 грузится на всех страницах, даже без форм.
- **Мёртвый груз:** старый Universal Analytics (`analytics.js`, UA-46179802-24) не работает с июля 2023 — грузится зря; gtag подключён дважды (UA + G-1HT7VBDGYW).
- Google-сервисы (reCAPTCHA, gstatic, GA) из РФ отвечают нестабильно — тормозят загрузку и **ломают отправку форм** (см. 2.4).

### 2.2 SEO on-page
- **Title главной** — только название компании. Главные коммерческие запросы («капитальный ремонт дизельных двигателей», «ремонт ЯМЗ» и т.д.) в title не участвуют.
- **Meta description главной обрезано на полуслове** («…настройку и регулировку»). У разделов «Услуги», «Продукция», «Контакты», «Новости» описаний **нет вовсе**; у «Вакансий» — мусор «Звоните по телефону: tel:+79828108169».
- **H1 главной** дублирует title (название АО), вместо услуг.
- **37 из 53 изображений без alt** — картиночный поиск и доступность потеряны.
- **og:image нет** — при шаринге в VK/Telegram/WhatsApp ссылка без картинки.

### 2.3 Структурированные данные — ноль
На сайте **нет ни одного JSON-LD блока**: ни `Organization`, ни `LocalBusiness`, ни `Service`, ни `Product`, ни `BreadcrumbList`, ни `FAQPage`. Rank Math установлен, но схема не настроена. Это главный упущенный рычаг и для сниппетов поисковиков, и для ИИ-ответов.

### 2.4 Формы и конверсия
- Формы CF7 защищены **Google reCAPTCHA v3** — из РФ скрипт периодически не грузится → заявка молча не уходит. Замена: Yandex SmartCaptcha / серверная honeypot-защита.
- Тексты на слайдах «вшиты» в картинки: не индексируются, не читаются скринридерами, нечитаемы на мобильном.

### 2.5 Безопасность/гигиена
- Нет security-заголовков (HSTS, X-Content-Type-Options, CSP, Referrer-Policy).
- Открытый `wp-json` REST API (перечисление контента и потенциально пользователей), `admin-ajax.php` разрешён в robots.
- WordPress + 8 плагинов = постоянная поверхность атак и обязанность обновляться.

## 3. GEO — видимость в ответах нейросетей (ChatGPT/Alice/GigaChat/Perplexity)

Что LLM-поисковики берут в ответ и чего сайту не хватает:

1. **`llms.txt` отсутствует** — новый стандарт «карты сайта для LLM» (список ключевых страниц + краткое описание компании в markdown).
2. **Нет политики для ИИ-краулеров** в robots.txt (GPTBot, ClaudeBot, PerplexityBot, YandexBot for GPT). Сейчас всё разрешено «по умолчанию» — для завода это правильно (нам НУЖНО попадать в ответы), но политику стоит зафиксировать явно.
3. **Факты не машиночитаемы.** LLM цитируют то, что легко извлечь: таблицы «модель двигателя → услуга → срок → гарантия», списки, Q&A. Сейчас ключевые факты размазаны по абзацам.
4. **Нет FAQ.** Страницы «Сколько стоит капремонт Д6?», «Какая гарантия?», «Как отправить двигатель в ремонт?» с разметкой `FAQPage` — главный формат, который LLM пересказывают дословно.
5. **Серия статей про Д6 — правильное направление** (42 поста, техруководства по диагностике/эксплуатации/консервации) — именно такой экспертный контент LLM берут в источники. Усилить: разметка `TechArticle`, автор, даты, перелинковка со страницами услуг.
6. **Внешние сигналы:** корректный NAP (название-адрес-телефон) в Яндекс Бизнес, 2ГИС, отраслевых каталогах (korabel.ru уже упомянут в закупках), упоминания в СМИ — LLM сверяют факты по нескольким источникам.
7. **Уникальная позиция не проговорена текстом.** «Один из немногих заводов РФ с испытательными стендами дизелей», «ремонт с 1931 года», «2000+ заказчиков» — эти утверждения должны быть на видных местах в чистом тексте, а не в картинках.

### 4.3 Найдено разбором кодовой базы 2026-08-22

Разбор шестью независимыми проходами (гейты, SEO, безопасность, скорость, доступность,
корректность), каждая находка затем **проверялась отдельным скептиком с задачей опровергнуть**.
Из 18 находок 9 отклонены как несуществующие, вкусовые или нарушающие принятые решения.
Ниже — выжившие.

**Статус доверия:** ✅✅ — перепроверено вручную по коду и живой прод-выдаче; ✅ — подтверждено
разбором (finder + скептик), но своими руками не воспроизводилось. Перед работой над ✅-пунктом
сначала воспроизвести, потом чинить.

**Закрыто (PR #42, 2026-08-22):**

- ✅✅ ~~`openGraph: … : undefined` стирал og-теги на страницах из `[...slug]`~~ — ключ со значением
  `undefined` Next понимает как «обнули», а не «наследуй». Соседние маршруты ключ не указывают
  вовсе и теги наследуют — эта разница дефект и маскировала. Гейт в `ci.yml` показан красным.
- ✅✅ ~~`/api/rezyume` рассылал письма на произвольный адрес из тела запроса~~ — `to: email` без
  валидации, а nodemailer читает `a@b.ru, victim@x.ru` как список получателей.
- ✅✅ ~~«← Назад» на экране отправки анкеты навсегда убивал виджет капчи~~ — контейнер внутри
  ветки `isLast`, эффект без cleanup, `widgetId` не сбрасывался. Приёмка на живом проде:
  12/12 → 2 iframe, «Назад» → 0, «Далее» → снова 2.

**Открыто, по убыванию отношения польза/цена:**

1. ✅ **Формы не покрыты ни одним гейтом.** В `.github/workflows/` нет ни одного POST: и CI, и
   смоук #011 состоят из GET. Отказ отправки заявки уедет на прод полностью зелёным, а завод
   узнает об этом по телефонному звонку. Инфраструктура уже есть — шаг «Контентные страницы
   рендерятся из БД» поднимает `next start` на наполненной БД, добавляется только `curl` + `psql`.
   Четыре проверки: успешный POST (первый хоп **200, не 308** — у нас `trailingSlash: true`),
   honeypot не создаёт записи, без `name` → 400, `/api/rezyume/` пишет запись с нужным `subject`.
   Мутация: переименовать поле в `payload.create` → шаг обязан упасть на `count=0`. **S**
2. ✅ **Поле «Содержимое» (richText) не рендерится ни на одной странице.** `Pages.ts` объявляет
   `content: richText`, а описание поля в `/admin` прямо велит редактору: «Для новых страниц
   оставьте пустым и заполните "Содержимое"». Фронт читает только `html` — редактор опубликует
   страницу, получит 200 и пустой `<div>`, и она уедет в `sitemap.xml` и `llms.txt`. Лечение:
   рендерить `<RichText data={page.content} />` при пустом `html` (пакет уже стоит). Гейт
   бесплатный: засеять страницу с пустым `html` и маркером в `content` — на текущем коде красный. **M**
3. ✅ **Тело POST не ограничено: 25 МБ парсится ДО капчи** при `MemoryMax=512M` на весь сайт.
   `client_max_body_size 25m` стоит в `location /` ради загрузок в админку и распространяется на
   формы; `limit_req`/`limit_conn` нет нигде. Капча тут не защита — она проверяется после
   `req.json()`. Дёшево и без прод-риска: ранний отказ `413` по `Content-Length` в обоих роутах.
   Дороже и с риском: отдельная `location ^~ /api/` в nginx — но тогда обязательно более длинный
   префикс для `/api/media` (иначе сломается загрузка файлов в админку) и дубль `proxy_set_header`
   (в новую локацию они не наследуются — иначе петля редиректов). **S** / **M+** соответственно.
4. ✅ **CSP нет вообще, а четыре security-заголовка пропадают на `/_next/static/`.** В nginx
   `add_header` наследуется с уровня выше только если на текущем уровне нет **ни одного** своего —
   а в `location /_next/static/` есть `Cache-Control`. Значит весь JS и CSS сайта отдаётся без
   `nosniff`, HSTS, `Referrer-Policy` и `X-Frame-Options`. Лечение: продублировать четыре заголовка
   в локации + завести CSP (`frame-ancestors`, `base-uri`, `object-src 'none'`, `form-action`,
   затем `script-src` с `mc.yandex.ru` и `smartcaptcha.yandexcloud.net`). **M**
5. ✅ **`pnpm lint` физически не может покраснеть от warning** — нет `--max-warnings 0`, а
   `exhaustive-deps` и `no-unused-vars` в этом проекте именно `warn`. Сейчас предупреждений **ноль**,
   поэтому правка зелёная с первого прогона и просто фиксирует состояние; после первых десяти
   warning порог уже не поставить. Красное снимается локально на PC40, без БД. **S** (G238)
6. ✅ **`lastmod` в `sitemap.xml` — дата харвеста, а не правки.** Берётся `publishedAt`, поэтому
   любая правка в `/admin` карту не двигает: у главной вечно стоит `2020-02-10`. Лечение —
   `updatedAt`. **S**
7. ✅ **34 контентные картинки главной грузятся eager** — 661 КБ до первого экрана, `loading="lazy"`
   нет ни у одной, а у первой миниатюры унаследован от WP `fetchpriority="high"`, конкурирующий
   с hero. CLS не грозит: `width`+`height` есть у всех 478 тегов контента. Лечение — переписывание
   `<img>` в рантайм-пути рендера. Единственная правка из списка, способная поломать вывод
   контента, — держать в отдельном PR. **S–M**
8. ✅ **Роут `/media` отдаёт только оригинал** — `doc.sizes` не читается вовсе, хотя коллекция
   генерирует `thumbnail`/`card`/`wide` при каждой загрузке. На записи 323 оригинал 651 КБ при
   готовом `card` 63 КБ. Просится вместе с п. 7: там же собирать `srcset`. **M**
9. ✅ **Подменю шапки недостижимы с клавиатуры** — `hidden group-hover:block`, то есть `display:none`:
   20 ссылок разделов вне таб-порядка (WCAG 2.1.1, уровень A). Правка в одну строку:
   `group-focus-within:block`. Заодно чинит планшет в альбомной ориентации, где hover не бывает. **S**
10. ✅ **Результат отправки форм не объявляется скринридеру, фокус теряется.** В `src/` ноль
    вхождений `aria-live`/`role="status"`/`role="alert"`; при успехе форма размонтируется вместе
    с кнопкой, на которой стоял фокус, и он падает на `<body>` (WCAG 4.1.3, AA). **M**
11. ✅ **Hero без `sizes`** — Next строит `srcSet` по DPR, и телефон предзагружает 83 КБ там, где
    хватило бы 24 КБ; плюс `height={420}` при реальных 400 в исходнике. Две строки, но **зависит
    от переезда v2** — трогать вместе с ним. **S**

**Отклонено скептиком** (записано, чтобы не искать заново): дубль gtag и Universal Analytics —
их у нас нет; «ноль автотестов» как самостоятельный дефект — чистых функций, оправдывающих
раннер, оказалось мало; контраст `.v2-label` ниже AA — реален, но живёт в noindex-превью и
переживёт переезд; `disallow: /new/` для группы ИИ-краулеров в `robots.ts` — реален, но снимется
самим переездом v2 на корень; fail-open капчи без `SMARTCAPTCHA_SERVER_KEY` — на проде ключ задан.
